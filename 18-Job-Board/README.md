# 18 - Job Board (Role-Based Access Control)

Welcome to Level 6! You are now building advanced applications. In this project, you will implement Role-Based Access Control (RBAC). Guests can only view jobs, but Admins can create and delete jobs.

## Learning Objectives
- Middlewares in Express for authorization.
- Sending HTTP Headers (`Authorization`) in `fetch`.
- Conditional Rendering in React based on User Role.

## Setup Instructions

### 1. Start the Backend
1. Terminal 1: `cd 18-Job-Board/backend`
2. `npm install`
3. `node index.js` (Runs on port 5000)

### 2. Start the Frontend
1. Terminal 2: `cd 18-Job-Board/frontend`
2. `npm install`
3. `npm run dev` (Runs on port 5173)

Click the green "Current Role: GUEST" button at the top to magically swap to an Admin and reveal the hidden features!

## Code Explanation

- **Express Middleware (`backend/index.js`)**: We wrote a function `requireAdmin(req, res, next)`. Before Express processes the `POST` or `DELETE` route, it runs this function. If the `Authorization` header doesn't match our secret token, it stops immediately and sends a 403 Forbidden error. If it does match, it calls `next()` to continue to the actual route logic.
- **HTTP Headers in Fetch**: In React, we added a `headers` object to our `fetch` request. We dynamically attach our secret token if `isAdmin` is true.
- **Conditional Rendering**: In `App.jsx`, we use `{isAdmin && (...) }` to completely hide the "Post Job" form and the "Delete" buttons if the user is not an admin.
